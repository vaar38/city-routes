## 3. Доработка индивидуального проекта

**Репозиторий:** https://github.com/vaar38/city-routes

**Структура базы** (`sql/schema.sql`, файл `data/city_routes.sqlite`):

| Таблица | Поля | Ключи |
|---|---|---|
| `interests` | `id` INTEGER, `name` TEXT NOT NULL UNIQUE | PK `id` |
| `users` | `id`, `name` TEXT, `email` TEXT UNIQUE, `interest_id` INTEGER | PK `id`, FK `interest_id → interests.id` |
| `routes` | `id`, `name` TEXT, `interest_id`, `length_km` REAL, `points_count` INTEGER, `description` TEXT (NULL допустим) | PK `id`, FK `interest_id → interests.id`; CHECK на длину и число точек |
| `recommendations` | `id`, `route_id`, `user_id`, `score` REAL, `is_dismissed` INTEGER 0/1 | PK `id`, FK `route_id → routes.id`, `user_id → users.id` |

Интерес, который в JSON был строкой у маршрута и пользователя, вынесен в отдельную таблицу `interests`; через неё маршрут и пользователь соединяются JOIN-ом при подборе. `CREATE TABLE IF NOT EXISTS` позволяет выполнять схему повторно.

**Модули Python:**
- `db/database.py` — `get_connection()` (`sqlite3.connect` + `PRAGMA foreign_keys = ON`), `create_schema()` (`executescript`), `fetch_all()` / `fetch_one()` с `row_factory = sqlite3.Row`;
- `db/import_json.py` — `python -m db.import_json`: схема → очистка таблиц → `executemany()` в порядке `interests → users, routes → recommendations` (внешние ключи требуют, чтобы родительская запись уже существовала) → `commit()`, при ошибке `rollback()`. Логическое `is_dismissed` из JSON приводится к 0/1.

**Проверка импорта:** `COUNT(*)` даёт 4 / 4 / 6 / 8 записей — совпадает с JSON-файлами (интересов 4 = различные значения `interest`); вставка рекомендации с несуществующим `route_id` отклоняется `IntegrityError: FOREIGN KEY constraint failed`.

**SQL-запросы** (`sql/queries.sql`, 17 запросов с комментариями):

| Вид | Запросы |
|---|---|
| выборка списков | 1 маршруты, 2 пользователи, 3 тематики |
| WHERE | 4 короткие маршруты, 5 поиск по тематике и длине, 6 маршрут по id, 7/8 активные рекомендации, 10 подбор с `NOT IN` |
| JOIN | 1, 5–10 (до четырёх таблиц), 13–17 (`LEFT JOIN` для групп без записей) |
| агрегатные функции | 11 `COUNT`/`AVG`/`MIN`/`MAX`/`SUM`, 12 `COUNT` активных |
| GROUP BY | 13 по тематикам, 14 по маршрутам, 15 по пользователям, 17 топ-3 с `LIMIT` |
| HAVING | 16 маршруты с активными рекомендациями больше порога |

**Страницы, получающие данные из SQLite** (`sqlite3.Row`, параметры `?`):

| URL | Сценарий |
|---|---|
| `/` | сводка: число маршрутов и активных рекомендаций |
| `/routes/`, `/routes/<id>/` | список маршрутов; карточка и кому маршрут рекомендован; 404 для несуществующего id |
| `/routes/search/?interest=&max_km=` | поиск по тематике и длине из GET-формы (`WHERE (? = '' OR …) AND (? IS NULL OR …)` — без склейки строк) |
| `/recommendations/`, `/recommendations/<id>/` | активные рекомендации (JOIN трёх таблиц), карточка (четыре таблицы) |
| `/recommendations/pick/?user=` | подбор маршрутов по интересу пользователя, ещё не рекомендованных ему |
| `/recommendations/statistics/?min=` | агрегаты, группировки, `HAVING` с порогом из формы, топ-3 |

Навигация: Главная | Маршруты | Рекомендации | Подбор | Статистика; поиск — ссылка со страницы маршрутов. JSON-хранилище и консольная версия `main.py` сохранены. `README.md` дополнен разделами «Текущий этап», «База данных», «Веб-интерфейс».
