## 2. Доработка индивидуального проекта

**Репозиторий:** https://github.com/vaar38/city-routes

Функции ПР2 и словари заменены объектной моделью. Модули `routes.py`, `users.py`, `recommendations.py` перенесены в пакет `models/`, в каждом — класс сущности и функции работы с коллекцией её объектов.

| Класс | Атрибуты | Методы |
|---|---|---|
| `Route` | `id`, `name`, `interest`, `length_km`, `points_count` | `is_suitable_for()`, `has_interest()`, `info` (`@property`), `validate_length()` (`@staticmethod`), `from_data()` (`@classmethod`), `__str__()` |
| `User` | `id`, `name`, `email`, `interest` | `change_interest()`, `from_data()` (`@classmethod`), `__str__()` |
| `Recommendation` | `id`, `route: Route`, `user: User`, `score`, `is_dismissed` | `dismiss()`, `is_active` (`@property`), `__str__()` |

**Что стало методом, а что осталось функцией.**

| Функция ПР2 | В ПР3 |
|---|---|
| проверки в `add_route()` / `add_user()` | перенесены в конструкторы `Route.__init__` / `User.__init__` |
| `check_route_length()` | логика — в `Route.is_suitable_for()`, функция ищет маршрут и вызывает метод |
| `change_interest()` | логика — в `User.change_interest()` |
| `dismiss_recommendation()` | ищет рекомендацию и вызывает `Recommendation.dismiss()`; объект остаётся в коллекции |
| `find_*`, `filter_*`, `sort_routes`, `show_*` | остались функциями: работают с коллекцией, а не с одним объектом |
| `load_*` / `save_*`, `input_*` | остались функциями в `storage.py` / `utils.py`: это не поведение сущности |

**Взаимодействие объектов.** `Recommendation` хранит ссылки на объекты `Route` и `User` (композиция): `rec.route.name`, `rec.user.email`. Правило предметной области сохранено: нельзя создать вторую *активную* рекомендацию того же маршрута тому же пользователю; отклонённая не мешает.

**JSON.** Формат файлов не изменился. `storage.py` превращает словари в объекты через `from_data()`, а при загрузке рекомендаций по `route_id` / `user_id` находит объекты и восстанавливает связи; запись со ссылкой на несуществующий объект пропускается. При сохранении ссылки снова превращаются в идентификаторы.

**Тесты и качество кода.** Тесты адаптированы к объектам и дополнены (создание объектов, `__str__`, `from_data`, `dismiss`, восстановление связей при загрузке) — 27 тестов `pytest` проходят, `flake8` без замечаний, у функций и методов есть аннотации типов.

## 3. Результат работы

- сущности проекта представлены классами `Route`, `User`, `Recommendation`;
- реализованы `__init__`, `__str__`, методы объектов, `@property`, `@staticmethod`, `@classmethod`;
- организовано взаимодействие объектов через композицию;
- функциональность ПР2 сохранена, коллекции содержат объекты;
- загрузка/сохранение JSON работают с объектной моделью;
- обновлены тесты и README.

## 4. Вывод

Данные и связанное с ними поведение объединены в объектах, функции модулей отвечают только за операции над коллекциями, а преобразование в JSON вынесено в `storage.py`. Объектная модель готова к использованию в веб-приложении на Django (ПР5).
